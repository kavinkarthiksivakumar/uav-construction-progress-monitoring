# Non-Negotiable Evidence Chain Standard & Classification Taxonomy

**Project Title**: Explainable Vision-Based Construction Progress Assessment and Delay Prediction Using Multi-Temporal UAV Imagery  
**SIH Problem Statement**: SIH1726  
**Document Code**: DOC-EVID-CHAIN-2026-V1  
**Audit Standard**: Non-Negotiable Evidence Rule  

---

## 1. Core Principle & The Non-Negotiable Rule

Every important result produced by this system—whether displayed on the interactive dashboard, delivered via RESTful API, or recorded in final examiner reports—must possess an immutable, unbroken evidence chain:

```
USER INPUT
    ↓
ACTUAL PROCESS EXECUTION
    ↓
INTERMEDIATE ARTIFACT
    ↓
COMPUTED RESULT
    ↓
VISUAL RESULT
    ↓
HUMAN-READABLE INTERPRETATION
```

> [!IMPORTANT]
> **Strict Anti-Fabrication Mandate**:
> Never generate a numerical result merely to complete the UI. If underlying computational ground truth, trained weights, or temporal pairs are insufficient, the system must display:  
> `NOT AVAILABLE — INSUFFICIENT VERIFIED INPUT/EVIDENCE`

---

## 2. Standardized 10-Point Evidence Structure

For every analytical stage, the following ten fields are explicitly recorded and persisted:

| Point | Evidence Field | Definition & Standard |
| :--- | :--- | :--- |
| **1** | **Input File / Inspection ID** | Exact source image filenames, flight timestamps, and database UUIDs. |
| **2** | **Processing Module** | Concrete pipeline subsystem executing the analysis (e.g. Module 1, Module 4, Module 5). |
| **3** | **Algorithm / Model Executed** | Specific algorithmic formulation (e.g. CLAHE + Otsu Thresholding, Sigmoidal S-Curve, Grad-CAM). |
| **4** | **Output Artifact Generated** | Physical file path on disk (e.g., `processed/module4/<pid>/mask.png`, `metadata/projects/<pid>/delay.json`). |
| **5** | **Numerical Result** | Exact computed metric. If ungrounded or absent, stores `NOT AVAILABLE — INSUFFICIENT VERIFIED INPUT/EVIDENCE`. |
| **6** | **Visual Evidence** | Direct URL to visual evidence artifact (e.g., difference overlay maps, Grad-CAM heatmaps, SHAP charts). |
| **7** | **Interpretation** | Human-readable engineering explanation translating data into construction management insight. |
| **8** | **Confidence / Quality Info** | Objective quality scoring (e.g., Laplacian blur variance, deterministic mathematical verification). |
| **9** | **Limitations** | Environmental, sensor, or algorithmic constraints (e.g., solar shadow drift, lack of subterranean visibility). |
| **10**| **Timestamp & Status** | Timezone-aware ISO-8601 UTC timestamp and verification status (`VERIFIED`, `EXECUTED`, `COMPUTED`). |

## 3. The Five Strict Categories of Evidence

The final examiner report strictly separates findings into five mutually exclusive categories. These categories must **never** be conflated:

### Category A: VERIFIED SOFTWARE FUNCTION
- **Definition**: Software functional verification, deterministic code logic, API contracts, image validators, and mathematical formulas tested via the automated QA harness.
- **Verification Evidence**: 159 of 159 automated Pytest unit and integration tests passing (100% pass rate in ~6.3 seconds, zero warnings).
- **Core Items**:
  - Image format whitelist & non-destructive byte header validation.
  - Cryptographic SHA-256 duplicate image detection.
  - Bounding box coordinate denormalization and scaling logic.
  - S-Curve logistic trajectory formula: $P_{\text{exp}}(t) = 100 / (1 + \exp(-\alpha (t/D - 0.5)))$.
  - Schedule variance calculation: $\Delta P = P_{\text{obs}} - P_{\text{exp}}$.

### Category B: VERIFIED MODEL OUTPUT
- **Definition**: Actual runtime outputs generated by executing computer vision and analytical models on this project's uploaded UAV imagery.
- **Verification Evidence**: Real disk artifacts generated in `processed/` directory with matching JSON metadata records.
- **Core Items**:
  - Actual Otsu bi-temporal difference mask and surface change % on project flight pairs.
  - Actual extracted connected change polygons and boundary coordinates.
  - Actual Roboflow class labels parsed and PPE safety compliance percentage derived.
  - Actual Grad-CAM spatial activation heatmaps computed for project keyframes.
  - Actual SHAP feature importance attributions calculated for progress derivation factors.

### Category C: DATASET BENCHMARK RESULT
- **Definition**: Quantitative empirical accuracy metrics computed by executing evaluation scripts on standardized external benchmark datasets.
- **Verification Evidence**: Real execution logs stored in `reports/evaluation/` from physical datasets on disk.
- **Core Items**:
  - **SYSU-CD (50 pairs)**: $\text{IoU} = 0.1852$, $F_1 = 0.2921$, $\text{Precision} = 0.2925$, $\text{Recall} = 0.4103$, $\text{Accuracy} = 72.85\%$.
  - **LEVIR-CD+ (50 pairs)**: $\text{IoU} = 0.0685$, $F_1 = 0.1118$, $\text{Precision} = 0.0757$, $\text{Recall} = 0.5717$, $\text{Accuracy} = 72.00\%$.
  - **Roboflow Site Safety (2,799 images)**: 38,835 physical annotations across 10 classes (`Person`: 10,031, `machinery`: 5,337, `Hardhat`: 3,551).

### Category D: QUALITATIVE OBSERVATION
- **Definition**: Visual evaluations, comparative structural observations, and expert engineering notes derived from imagery review.
- **Verification Evidence**: Review of orthophoto visual artifacts and spatial overlays.
- **Core Items**:
  - Visible progress across foundation footings and ground-floor slab formwork between flights.
  - Active heavy excavator deployed in western foundation sector.
  - Static non-construction features (access roads, boundary fences) remain invariant with near-zero difference noise.

### Category E: UNAVAILABLE / NOT YET VALIDATED
- **Definition**: Features, weights, or external services that are absent or pending external verification. Explicitly labeled to prevent black-box deception.
- **Verification Evidence**: Transparent disclosure in reports and UI badges.
- **Core Items**:
  - Custom deep YOLOv8 weights (`.pt` file omitted; operates in Roboflow benchmark verification mode).
  - 3D photogrammetric cut-and-fill volumetric excavation metrics (requires dense stereo point cloud meshing).
  - Subterranean and interior MEP installation progress (unobservable purely from aerial optical cameras).
  - Official institutional Turnitin plagiarism certificate (pending external supervisor execution).
  - Formal Scopus paper indexing certification (manuscript prepared for submission to *Automation in Construction*; indexing occurs only after formal acceptance).

## 4. Implementation & Audit Locations

1. **Backend Engine**: `backend/modules/decision_support/evidence_report.py` (`create_evidence_chain()`, `build_evidence_report()`).

4. **Automated Test Suite**: `tests/test_decision_support.py` (`TestEvidenceReport` validates all 10 fields and 5 categories).
